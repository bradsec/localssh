# iOS background session continuity: solution architecture

**Frame:** Designing short background continuity for browser SSH, prioritizing security, correct byte delivery, and low operating cost under iOS page suspension. Exact survival until explicit disconnect is impossible while SSH state exists only in an evictable page.

## Requirements and evidence

- R1 | Preserve the authenticated SSH and PTY session when the same page returns soon after backgrounding. Do not treat a temporary WebSocket loss as a user disconnect.
- R2 | Preserve SSH byte order, without dropping or duplicating encrypted bytes across a WebSocket replacement. Preserve per-tab isolation and the relay's inability to decrypt SSH.
- R3 | Bound orphaned TCP sockets, memory, and token lifetime. Make expiry and data loss visible, never claim a dead session resumed.
- R4 | Support an evicted page by reporting that the SSH session is gone and offering a fresh verified login. Remote process persistence beyond a bounded grace requires `tmux` or `screen` on the SSH host.
- Assumptions | Self-hosted LAN use, existing Node 26 relay and Go WASM engine, no application accounts, no server-side credential custody. User count, typical background duration, SSH server idle policy, reverse proxy identity, and memory budget are **unmeasured**; proposed limits below are starting values, not capacity claims.
- Evidence | `App.tsx:177-189` closes every handle on `pagehide`; `engine/wsconn/wsconn.go` turns WebSocket close into `net.Conn` EOF; `engine/main.go:274-279` then closes SSH; `relay/src/local-relay.ts:279-284` destroys TCP on WebSocket close. `sshclient/client.go:17-19,157,165-191` sends SSH keepalives every 15 seconds and closes after three missed intervals. Confidence **HIGH**, source inspection, 2026-11-02.
- Browser constraint | WebKit says iOS tabs can be completely suspended; MDN describes WebSocket closure and page restoration around bfcache. This supports a reconnect design, not an uptime guarantee. Confidence **HIGH** for possibility of suspension, **MED** for exact behavior on this app and iOS versions, which needs device testing. [WebKit power guidance, accessed 2026-11-02](https://webkit.org/blog/8970/how-web-content-can-affect-power-usage/); [MDN WebSocket lifecycle, accessed 2026-11-02](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_client_applications).

## Architecture and data flow

```text
React tab and xterm -> Go WASM SSH state -> resumable wsconn -> WebSocket
                                                    |           |
                                               encrypted SSH    v
                                          Node relay session -> TCP -> SSH host
```

The Go engine owns SSH keys, packet sequence, channel state, and SFTP. The relay owns only a live TCP socket, opaque encrypted bytes, byte offsets, expiry, and a resume capability. React owns tab identity and visible states: Connected, Reconnecting, Session expired. A reconnect reattaches the **same WASM `net.Conn` and SSH session**, rather than calling `sshConnect` again.

**Protocol v2, proposed:** Keep the current `{host,port}` connect path as v1 for older pages. A v2 `connect` frame requests resumption support; the relay validates origin and target, opens TCP, then returns `ready(sessionId, token, expiresAt, limits)` before any raw SSH bytes. On WebSocket loss, the relay retains TCP for a **proposed 120-second grace**. A new WebSocket sends `resume(sessionId, token, clientAck, serverAck)` as its first frame. The relay validates the token, original origin, session state, and expiry, then atomically attaches one socket and returns `resumed` with offsets. No target host or credential comes from the resume request. Reject a second live attachment; a stale half-open socket needs an explicit transport-detach or bounded liveness timeout before replacement. One relay instance owns each session; a proxy must route resume to it, or return an expired result. No cross-instance state store is proposed.

**Byte continuity:** v2 frames carry direction, monotonic byte offset, and opaque payload. Each side retains unacknowledged bytes, acknowledges only bytes accepted by its stream consumer, replays from the last acknowledged offset, and ignores duplicate offsets. The Go `net.Conn` must keep reads and writes pending during transport loss, not return EOF until resume fails or the session expires. The relay must retain target output even if the old WebSocket accepted a send; WebSocket send completion does **not** prove WASM consumed it. For client input, relay acknowledgement follows ordered acceptance into the TCP socket; replay must not write an already accepted range twice. Sequence mismatch, missing retained bytes, or conflicting duplicate payload closes the SSH session with a specific error. This framing and accounting are necessary for correctness; a bare reconnect with a FIFO output buffer is unsafe.

On `visibilitychange` to hidden or `pagehide`, the page attempts a v2 transport-detach and pauses SSH keepalives. Delivery of that event is optional: unexpected WebSocket close follows the same detached path. On `pageshow`, visible transition, or detected socket loss, retry resume with bounded backoff until the grace deadline. Resume immediately restarts the existing Go SSH reader and keepalive loop; React keeps terminal state and tabs. Explicit Disconnect, shell exit, relay shutdown, target failure, token expiry, or unrecoverable offset mismatch closes SSH and TCP. `FilePanel` may release a held browser download on `pagehide`; in-flight SFTP over the shared SSH channel must either resume safely or fail visibly without implying upload/download completion.

## Decisions

| ID | Decision | Why | Rejected choice and reason | Rules out; revisit if |
| --- | --- | --- | --- | --- |
| D1, one-way contract | Keep SSH in Go WASM; add a versioned resumable relay transport. | Retains client-side authentication and host-key checking. **HIGH**, repository source and [RFC 4253 SSH transport](https://www.rfc-editor.org/rfc/rfc4253), accessed 2026-11-02. | Moving SSH to the relay would require credentials, host-key trust, and plaintext I/O there. | No seamless recovery after page eviction; revisit only if product accepts a server-side SSH trust boundary. |
| D2, reversible policy | Retain TCP for 120 seconds after detach; cap retained unacknowledged bytes at 256 KiB per direction per session and 16 MiB across detached sessions. Pause TCP reads at the cap, then expire the oldest detached session if the global cap is reached. | Gives short phone switches a recovery window and bounds memory. **LOW** for adequacy: workload unmeasured. | Unlimited retention permits resource exhaustion; immediate close preserves today's failure. | Long-running noisy jobs may block on SSH flow control; tune from measured detach durations and output rates. |
| D3, one-way contract | Sequence and acknowledge opaque SSH bytes in both directions. | Prevents loss and duplicate input at the WebSocket boundary. **HIGH**, transport reasoning and current `wsconn`/relay code. | Buffer-only reattach cannot tell whether old WebSocket delivery reached WASM. | Adds protocol and state-machine complexity; revisit only with a proven simpler lossless transport. |
| D4, reversible policy | Use a random 256-bit, single-session bearer token in page memory, scoped to original origin and relay lifetime; never put it in URL, browser storage, or logs. | Limits replay and disclosure; relay still cannot decrypt SSH. **MED**, design judgment, pending security review. | Origin-only resume is forgeable outside browsers and unsafe with `ALLOWED_ORIGINS=*`; persistent token storage lengthens theft window. | No reattach after page eviction; revoke on explicit disconnect and expiry. |
| D5, reversible product choice | Document optional host-managed `tmux`/`screen` for work that must survive expiry or page eviction. | A fresh, verified SSH login can reattach a remote shell. **HIGH** for architectural boundary, [RFC 4253](https://www.rfc-editor.org/rfc/rfc4253), accessed 2026-11-02. | Relay-side SSH persistence changes the security model; TCP grace alone cannot restore evicted crypto state. | No automatic resurrection of the same SSH connection or SFTP transfer. |

## Failure, consistency, scaling, security

- F1 | iOS suspends JavaScript: Go SSH keepalives stop. TCP keepalive from the Node socket can help detect dead network paths, but cannot answer SSH application keepalives or override a server's idle policy. The server may close during grace. Confidence **HIGH** for protocol distinction; [Node 26 `net.Socket.setKeepAlive`](https://nodejs.org/api/net.html#socketsetkeepaliveenable-initialdelay), accessed 2026-11-02. Test actual target servers.
- F2 | Page evicted, reloaded, or WASM instance lost: encrypted SSH state is gone. Expire the orphan at 120 seconds; reconnect with normal credentials and host-key verification. `tmux` may restore remote shell work, not SSH or SFTP state.
- F3 | Relay restart, proxy route change, target TCP close, or server timeout: in-memory session disappears. Show Session expired and require a new SSH login. Deployment restarts interrupt retained sessions; do not advertise uninterrupted upgrades.
- F4 | Output exceeds retention: stop TCP reads, backpressure the SSH server, and expire at grace deadline or global memory pressure. Input writes wait in a bounded Go queue; reject further input visibly at its cap. A browser WebSocket's own buffer must also be bounded.
- F5 | Token theft: attacker can seize or disrupt the relay TCP stream, even though SSH encryption prevents reading or forging authenticated SSH packets. Require HTTPS/WSS for network-exposed use, secure the page against script injection, check origin and authenticated proxy identity where available, rate-limit failed resume attempts, and audit accepted/rejected resumes without tokens. Existing wildcard origin mode increases exposure. Security review must decide whether to allow v2 on unauthenticated public deployments.
- F6 | Consistency is per-session ordered and at-most-once TCP byte acceptance after deduplication; ACK and replay give eventual delivery only while both endpoints and retained state survive. No distributed consistency or transparent failover is claimed. Each detached session consumes a TCP socket and bounded memory. Existing `MAX_SESSIONS=256` counts WebSockets, so capacity enforcement must count **active plus detached sessions**, not just `wss.clients.size`.

## Operability and build sequence

1. Measure on real iPhones: background durations, whether page resumes or reloads, socket-close timing, SSH server idle settings, and peak output/input while detached. Confirm the proposed 120-second/256-KiB/16-MiB budgets with the host's RAM and expected session count. Current capacity confidence **LOW**.
2. Add protocol v2 and relay session accounting behind an opt-in setting. Keep v1 behavior and access checks intact. Unit-test frame validation, token secrecy and expiry, duplicate/overlap offsets, byte caps, origin checks, one attachment, target close, and shutdown cleanup.
3. Add resumable `wsconn` with bounded queues and a Go integration test: drop WebSocket after bytes enter either sender's buffer but before receiver acknowledgement; verify a real SSH command runs once and its output matches exactly. Cover keepalive pause/resume, expiry, deliberate disconnect, and SFTP interruption.
4. Wire React reconnecting/expired states and page lifecycle. Test multiple tabs, `pagehide`/`pageshow`, hidden/visible transitions, relay outage, and no stale handle use. Run real iOS Safari device tests, including lock screen, app switch, poor network, and page eviction. Roll out to one self-hosted installation; record detach count, resume success/latency, expiry cause, buffered-byte high water, and session count without logging SSH payloads or tokens. Roll back by disabling v2 and returning to v1 connections; existing v2 sessions end on rollback.
5. Update README, user guide, deployment limits, and proxy routing guidance when behavior ships. Defer remote multiplexer automation, shared session storage, and server-side SSH until measured need or a changed security requirement justifies them.

**Handoff and verification:** Engineering owns the v2 offset/ACK invariant, lifecycle state machine, and integration tests. Security owns token threat review, proxy identity, and public deployment policy. Operations owns memory/socket budgets, single-instance routing, and SSH server timeout validation. Node `setKeepAlive` behavior above is documented for Node 26; confirm deployed Node version and OS settings. No vendor quota or price governs this self-hosted design. SSH server timeout values, iOS lifecycle behavior on supported devices, and actual workload remain **SUSPECTED** until measured.
